# tock

作業の開始・停止をコマンドで打刻して、タグ別・日次/週次に集計するローカル完結の作業時間トラッカー。

記録はすべて自分のマシンのファイルに保存される。外部 API・アカウント・ネットワーク接続は
一切使わない。

```console
$ tock start "設計 #work"
開始しました: 設計 [#work]
開始時刻: 18:00:00
$ tock stop
停止しました: 30m
終了時刻: 18:30:00
$ tock today
2026-08-12
work  30m
合計  30m
```

## 必要なもの

- Node.js 22.12.0 以降

## インストール

npm では未公開なので、リポジトリから入れる。

```console
$ git clone https://github.com/okrago10/loop-demo.git
$ cd loop-demo
$ npm ci
$ npm run build
$ npm link
$ tock --version
0.1.0
```

`npm link` を使わない場合は、ビルド済みの入口を直接叩いてもよい。

```console
$ node dist/cli.js --version
0.1.0
```

以降の例では `tock` と書く。

## クイックスタート

打刻してから今日の合計を見るまでが一巡り。**そのまま貼れる**（時刻の指定を含まないので、
何時に実行しても通る）。

```console
$ tock start "設計 #work"
開始しました: 設計 [#work]
開始時刻: 18:00:00
$ tock status
実行中: 設計
タグ: #work
経過: 30m
開始: 18:00:00
$ tock stop
停止しました: 1h
終了時刻: 19:00:00
$ tock today
2026-08-12
work  1h
合計  1h
```

`"設計 #work"` の `#work` の部分がタグになり、残りが作業名になる。集計はタグごとに出る。

## コマンド

`tock --help` でコマンドの一覧、`tock <command> --help` でそのコマンドの使い方が出る。
以下は同じ内容を、実行例つきで並べたもの。

> **時刻の見え方について。** 画面に出る時刻は**実行環境のローカル時刻**で、`--at` の
> 解釈と同じ基準になる。`--at 09:00` と打てば `09:00:00` と出る。**その日のうちなら時刻だけ、
> 別の日なら日付も付く**（`2026-08-14 00:10:00`）——前日から実行中の記録が今日のものに
> 見えないようにするため。
>
> **保存と `tock export` は ISO 8601 の UTC（末尾が `Z`）のまま。** 機械が読む形式なので、
> 地域や表記の揺れを持ち込まない。画面向けの表記とは別に扱う。
>
> どのタイムゾーンで解釈するかを設定で選べるようにするのは #64 の担当で、いまは実行環境の
> ゾーンに従う。

### tock start

作業を開始する。

| オプション | 意味 |
| --- | --- |
| `--at HH:MM` | 開始時刻を指定する（省略すると現在時刻） |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
```

実行中の作業があるときに `start` すると失敗する。切り替えたいときは `tock switch` を使う。

**`--at` に未来の時刻は指定できない。** 打ち忘れを後から入れるためのオプションなので、
過ぎた時刻しか受け付けない。

```console
$ tock start "打ち間違い" --at 23:59
--at に未来の時刻は指定できません: 23:59（現在は 18:00:00）
$ echo $?
1
```

### tock stop

実行中の作業を終了する。

| オプション | 意味 |
| --- | --- |
| `--at HH:MM` | 終了時刻を指定する（省略すると現在時刻） |
| `--note テキスト` | 作業名を上書きする |
| `--auto` | 止め忘れを上限の時刻（既定 8 時間）で打ち切る |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
```

`--auto` は**止め忘れを畳むための指定**。開始から上限（既定 8 時間。設定は
`maxRunningHours`）を超えていれば、その上限の時刻で打ち切って確定する。まだ上限に
届いていなければ「今」で止まり、`--auto` を付けない場合と同じ結果になる——届いていない
記録に上限を当てると未来の終了時刻になり、記録として作れないため。

終了時刻の決め方が2つになるので、`--at` とは同時に指定できない。

実行中の作業がなければ失敗する。打ち忘れに気づけるように、黙って成功はしない。

```console
$ tock stop
実行中の作業がありません。tock start で開始してください
$ echo $?
1
```

### tock status

実行中の作業を表示する。

| オプション | 意味 |
| --- | --- |
| `--short` | 1行だけ出す（プロンプトやステータスバー向け） |

```console
$ tock start "実装 #work/tock" --at 13:00
開始しました: 実装 [#work/tock]
$ tock status --short
実装 #work/tock 5h 30m
```

実行中の作業がなくても失敗しない（終了コードは 0）。

```console
$ tock status
実行中の作業はありません。tock start で開始してください
```

### tock switch

実行中の作業を終了して、次の作業を開始する。`stop` と `start` を1回で行う。

| オプション | 意味 |
| --- | --- |
| `--at HH:MM` | 切り替える時刻を指定する（省略すると現在時刻） |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock switch "定例 #会議" --at 11:00
停止しました: 2h
開始しました: 定例 [#会議]
```

前の作業の終了時刻と次の作業の開始時刻は同じになるので、間に隙間ができない。

### tock today

今日のタグ別合計を表示する。

| オプション | 意味 |
| --- | --- |
| `--chart` | タグ別合計を横棒グラフで表示する |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock start "定例 #会議" --at 11:00
開始しました: 定例 [#会議]
$ tock stop --at 11:45
停止しました: 45m
$ tock today
2026-08-12
work       1h 30m
work/tock  1h 30m
会議       45m
合計       2h 15m
```

`work/tock` の時間が親の `work` にも合算されている。詳しくは「タグ」を参照。

実行中の作業も、その時点までの経過時間として数える。

### tock summary

指定した日のタグ別合計を表示する。

| オプション | 意味 |
| --- | --- |
| `--day YYYY-MM-DD` | 集計する日（省略すると今日） |
| `--chart` | タグ別合計を横棒グラフで表示する |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock summary
2026-08-12
work       1h 30m
work/tock  1h 30m
合計       1h 30m
```

`--chart` を付けると、同じ集計が横棒グラフになる。**バーの長さは端末幅に追従し、
いちばん大きい値を基準に正規化する。** 数字も並べて出すので、バーだけで値が読めない
ということはない。合計の行はグラフに入れない——合計は必ず最大値になるので、満杯のバーが
1本立つだけで他の行の比を潰してしまう。

記録が1件も無い日を指定すると、そのことが1行で出る（終了コードは 0）。

```console
$ tock summary --day 2026-08-01
2026-08-01
記録がありません
```

### tock log

記録を新しい順に一覧表示する。

| オプション | 意味 |
| --- | --- |
| `--period 期間` | 期間で絞る（`today` / `this-week` / `2026-08-12` など） |
| `--tag タグ` | タグで絞る（階層タグは親でも一致する） |
| `--limit 件数` | 表示する件数（既定 20） |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock start "定例 #会議" --at 11:00
開始しました: 定例 [#会議]
$ tock stop --at 11:45
停止しました: 45m
$ tock log
6d74145b  2026-08-12  11:00-11:45  45m     定例 #会議
c01fa0f5  2026-08-12  09:00-10:30  1h 30m  設計 #work/tock
$ tock log --period today --tag work --limit 1
c01fa0f5  2026-08-12  09:00-10:30  1h 30m  設計 #work/tock
```

左端が **id**（記録を指すための識別子）。`edit` と `rm` にはこれを渡す。実行中の記録は
終了時刻の欄が `実行中` になる。

id は記録ごとに決まるので、この README の例に出ている値をそのまま打っても一致しない。
自分の `tock log` に出ているものを見て渡す。

### tock week

週のタグ別・曜日別の集計を表示する。

| オプション | 意味 |
| --- | --- |
| `--offset 週数` | 週のずらし（`-1` が先週、`1` が翌週。既定 0 = 今週） |
| `--week-starts-on 曜日` | 週の開始曜日（0 が日曜。設定より優先） |
| `--heatmap` | 曜日 × 時間帯のヒートマップで表示する |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock week
2026-08-10 〜 2026-08-16
           月  火  水      木  金  土  日  合計
work       0s  0s  1h 30m  0s  0s  0s  0s  1h 30m
work/tock  0s  0s  1h 30m  0s  0s  0s  0s  1h 30m
合計       0s  0s  1h 30m  0s  0s  0s  0s  1h 30m
```

`--heatmap` を付けると、タグ別の表ではなく**曜日 × 時間帯**の図になる。同じ週の同じ記録を、
「何のために使ったか」ではなく「何時に働いたか」で見る。1時間を1桁で描くので幅は端末に
追従しない——濃淡は値の比であって長さではなく、詰めても意味が変わらないため。

週の開始曜日は既定で月曜。変えたいときは設定（`weekStartsOn`）か `--week-starts-on` を使う。

### tock edit

記録を修正する。id は `tock log` の左端に出ているものを渡す（先頭の数文字でよい）。

| オプション | 意味 |
| --- | --- |
| `--start HH:MM` | 開始時刻を直す（記録の開始日に適用する） |
| `--end HH:MM` | 終了時刻を直す（記録の終了日に適用する） |
| `--tags "a b"` | タグを置き換える（空文字で消す） |
| `--note テキスト` | 作業名を置き換える |

以下の `<id>` は、`tock log` に出ている id に読み替える。

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock log
a2e4af24  2026-08-12  09:00-10:30  1h 30m  設計 #work/tock
$ tock edit <id> --note "設計レビュー" --end 11:00
修正しました: 設計レビュー #work/tock
id: a2e4af24
$ tock log
a2e4af24  2026-08-12  09:00-11:00  2h  設計レビュー #work/tock
```

**時刻は記録自身の日付に適用される。** 3日前の記録を直しても今日へは動かない。
日付そのものを変えることはできない（下の「今できないこと」を参照）。

### tock rm

記録を削除する。

| オプション | 意味 |
| --- | --- |
| `--yes` | 確認を尋ねずに削除する（対話端末でないときは必須） |

```console
$ tock start "打ち間違い #work" --at 09:00
開始しました: 打ち間違い [#work]
$ tock stop --at 09:01
停止しました: 1m
$ tock log
3f9c1d20  2026-08-12  09:00-09:01  1m  打ち間違い #work
$ tock rm <id> --yes
削除しました: 打ち間違い #work
id: 3f9c1d20
```

`--yes` を付けないと確認を尋ねる。パイプやスクリプトから実行した場合は答えを受け取れない
ので、`--yes` が必要になる。

存在しない id を渡すと失敗する。

```console
$ tock rm deadbeef --yes
その id の記録がありません: deadbeef
$ echo $?
1
```

### tock export

記録を CSV / JSON で書き出す。標準出力に出るので、リダイレクトでファイルに保存する。

| オプション | 意味 |
| --- | --- |
| `--format csv\|json` | 書き出す形式（設定 `defaultFormat` がなければ必須） |
| `--period 期間` | 期間で絞る（省略すると全期間） |
| `--sanitize` | CSV で数式として読まれる値を無害化する |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock export --format csv
id,start,end,duration_min,tags,note
c01fa0f5-cbe6-470a-8550-ccf8caa4438d,2026-08-12T09:00:00.000Z,2026-08-12T10:30:00.000Z,90,work/tock,設計
```

CSV は完全な id（短縮していないもの）を出す。実行中の記録は `end` と `duration_min` が空欄になる。

設定に `defaultFormat` を書いておくと `--format` を省ける。書いていなければ省けない
（形式を選んでいない状態で書き出すと、できたファイルが csv か json か分からなくなる）。

```console
$ tock config set defaultFormat csv
設定しました: defaultFormat=csv
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock export
id,start,end,duration_min,tags,note
c01fa0f5-cbe6-470a-8550-ccf8caa4438d,2026-08-12T09:00:00.000Z,2026-08-12T10:30:00.000Z,90,work/tock,設計
```

#### 表計算ソフトで開くときの注意

Excel / Google スプレッドシート / Numbers は、**`=` `+` `-` `@` で始まるセルを数式として
読む。** 作業名を `=1+1` にした記録を書き出して開くと、`2` と表示されて元の作業名が読めない。

**既定では値を変えずに書き出す。** 書き出したものをそのまま読み戻せることを優先しているため。
表計算ソフトで開くなら `--sanitize` を付ける。先頭に `'` を足して数式として読まれないようにする。

```text
（既定）      note の列が =1+1
--sanitize    note の列が '=1+1
```

**`--sanitize` は値を書き換える。** 読み戻して記録として扱う用途には使わない。`--format json`
との併用はできない（JSON は再取り込みのための形式なので、値を変えると別の記録になる）。

**引用符では防げない。** `"=1+1"` と囲んでも表計算ソフトは中身を数式として読む。CSV の引用規則
（カンマ・引用符・改行のためのもの）とは別の層の話になる。

無害化するのは `=` `+` `-` `@` とタブ・CR で始まる値。**先頭が空白の場合（`" =1+1"`）は
この版では対象外**で、Excel は先頭の空白を落としてから数式と読むことがある。ただし `tock start` も
`tock edit` も前後の空白を落とすので、この形になるのは記録のファイルを手で書き換えたときだけ。


JSON は記録の配列として出る。

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock export --format json --period today
[
  {
    "id": "c01fa0f5-cbe6-470a-8550-ccf8caa4438d",
    "start": "2026-08-12T09:00:00.000Z",
    "end": "2026-08-12T10:30:00.000Z",
    "tags": [
      "work/tock"
    ],
    "note": "設計"
  }
]
```

### tock config

設定を読み書きする。オプションはない。

```console
$ tock config get
weekStartsOn=1
rounding.unitMinutes=
rounding.mode=
maxRunningHours=8
defaultFormat=
$ tock config set weekStartsOn 0
設定しました: weekStartsOn=0
~/.tock/config.json
$ tock config get weekStartsOn
0
```

`get` でキーを省略すると全項目を出す。**値が空の行は「設定していない」**という意味で、
そのキーは既定のまま扱われる。`set` の2行目に出るのが**書き込んだ設定ファイルのパス**
（`TOCK_DIR` を指定していればそちら）。設定できる項目は「設定」を参照。

## タグ

作業名の中に `#` で書いた語がタグになる。残りが作業名（note）になる。

```console
$ tock start "定例 #会議 #proj/tock" --at 11:00
開始しました: 定例 [#会議 #proj/tock]
```

- タグは複数書ける
- `/` で区切ると**階層タグ**になる。`#work/tock` は `work` にも合算される
- 集計（`today` / `summary` / `week`）はタグごとに行を出す
- `tock log --tag work` は `work/tock` の記録にも一致する（親で絞れる）

## 期間の指定

`--period` は次の書き方を受け付ける。

| 書き方 | 意味 |
| --- | --- |
| `today` | 今日 |
| `yesterday` | 昨日 |
| `this-week` | 今週（週の開始曜日は設定に従う） |
| `last-week` | 先週 |
| `this-month` | 今月 |
| `2026-08-01` | その日 |
| `2026-08-01..2026-08-07` | その範囲（両端の日を含む） |
| `-7d` | 今日を含む直近7日 |

```console
$ tock start "設計 #work/tock" --at 09:00
開始しました: 設計 [#work/tock]
$ tock stop --at 10:30
停止しました: 1h 30m
$ tock log --period -7d
c01fa0f5  2026-08-12  09:00-10:30  1h 30m  設計 #work/tock
```

## 図の表示

`--chart` と `--heatmap` は、**出力先が対話端末かどうかで見た目を変える。**

| 出力先 | バー | ヒートマップの濃淡 |
| --- | --- | --- |
| 端末 | `█` | `.` `░` `▒` `▓` `█` |
| パイプ・リダイレクト | `#` | `.` `-` `+` `*` `#` |

パイプの先がブロック文字を表示できるとは限らず、`grep` や `diff` にかけたときにも
邪魔になるため、装飾は落とす。**長さと濃淡の段階は変えない**ので、パイプ越しに見た図と
端末で見た図で読み取れることは同じになる。

**色（ANSI エスケープ）は使わない。** 濃淡は文字だけで表す。`NO_COLOR` や `TERM=dumb` の
扱いを持ち込まずに済ませるためで、どちらの出力先でも色は出ない。

## 設定

| キー | 値 | 既定 |
| --- | --- | --- |
| `weekStartsOn` | 0（日曜）〜6（土曜）の整数 | 1（月曜） |
| `rounding.unitMinutes` | 1以上の整数（分） | 未設定（丸めない） |
| `rounding.mode` | `ceil` / `floor` / `nearest` | 未設定（丸めない） |
| `maxRunningHours` | 1以上の整数（時間） | 8 |
| `defaultFormat` | `csv` / `json` | 未設定（`tock export` に `--format` が必要） |

設定は次の優先順位で決まる。**左が強い。**

```text
コマンドラインオプション > 環境変数 > 設定ファイル > 既定値
```

環境変数の名前はキーから決まる（`weekStartsOn` なら `TOCK_WEEK_STARTS_ON`、
`rounding.unitMinutes` なら `TOCK_ROUNDING_UNIT_MINUTES`）。

設定ファイルは JSON で、`tock config set` が書く。**ドットを含むキーは入れ子になる。**

```json
{
  "weekStartsOn": 0,
  "rounding": { "unitMinutes": 15, "mode": "ceil" }
}
```

読めない値が書かれていても打刻や集計は止まらない。その値だけ既定値に落とし、警告を出す。

### 止め忘れの警告

実行中の作業が `maxRunningHours`（既定 8 時間）を超えていると、**どのコマンドを打っても**
stderr に警告が出る。「stop を押し忘れて12時間計測されていた」に気づけるようにするため。

警告は失敗ではないので終了コードは変わらず、stdout にも混ざらない（集計をパイプで
読んでいる側が壊れない）。実際に止め忘れていたときは `tock stop --auto` で上限の時刻に
打ち切れる。**勝手には止めない**——自動で確定させると、本当に長時間続けた作業まで切られる。

### 丸め

`rounding` を設定すると、**集計の表示だけ**が丸まる。工数報告で「15分単位」のような
粒度が要るときに使う。

```console
$ TOCK_ROUNDING_UNIT_MINUTES=15 TOCK_ROUNDING_MODE=ceil tock today
```

- **単位と丸め方の両方を設定して初めて効く。** 片方だけでは「15分単位でどちらに寄せるか」
  が決まらないので、丸めない。片方だけ書いた場合は、効かないまま黙らずに警告を出す
- 丸まるのは `summary` / `today` / `week` の表。`log` / `export` / `status` と
  **保存された記録は実測のまま**——機械が読む値に表示の判断を焼き込まない
- 長さ 0 の記録は `ceil` でも 0 のまま。記録していない時間を報告に載せないため
- `week` は**表示するセルを丸め、行の合計はその和**にする。こうすると各行が横に閉じる。
  そのぶん総合計は真の合計から数分ずれることがあるが、**表が閉じていないほうが害が大きい**
- **`合計` 行はタグ別の行を縦に足したものではない。** 階層タグは同じ時間を複数の行に出す
  （`#work/tock` の時間は `work` の行にも入る）ので、縦に足すと二重に数える。`合計` 行は
  その日・その曜日の**実時間**を丸めたもので、これは丸めを入れる前からの性質

## データの保存場所

| ファイル | 中身 |
| --- | --- |
| `~/.tock/entries.jsonl` | 記録 |
| `~/.tock/config.json` | 設定 |

`TOCK_DIR` を指定すると、その両方の置き場所が変わる。

```console
$ TOCK_DIR=/tmp/tock-trial tock start "試し #work"
開始しました: 試し [#work]
```

記録は1行1操作の JSONL で、追記だけを行う。既にある行は書き換えない。

```jsonl
{"v":2,"op":"append","entry":{"id":"a2e4af24-2074-4afc-b785-89bba74b4f69","start":"2026-08-12T09:00:00.000Z","tags":["work/tock"],"note":"設計"}}
{"v":2,"op":"update","entry":{"id":"a2e4af24-2074-4afc-b785-89bba74b4f69","start":"2026-08-12T09:00:00.000Z","end":"2026-08-12T10:30:00.000Z","tags":["work/tock"],"note":"設計"}}
```

読み出すときに先頭から畳み込んで現在の状態を作る。**壊れて読めない行は飛ばす**（1行の破損で
すべての記録が読めなくなるより損失が小さい、という判断）。

### 保存形式のバージョン

各行の `v` が保存形式のバージョンで、**この版が書くのは `v:2`**。`tock switch` の停止と開始を
1行にまとめた `op:"switch"` は、このバージョンで入った。

```jsonl
{"v":2,"op":"switch","stop":{"id":"a2e4af24-…","start":"2026-08-12T09:00:00.000Z","end":"2026-08-12T11:00:00.000Z","tags":["work/tock"],"note":"設計"},"start":{"id":"7cb74990-…","start":"2026-08-12T11:00:00.000Z","tags":["work/tock"],"note":"レビュー"}}
```

**古い版で書いたファイルは、この版でそのまま読める**（`v:1` の行、`v` の無い行を含む）。
逆はできない。**この版で1行でも書き足したファイルは、`v:2` を知らない古い版では開けなくなり、
「新しい版の tock で開いてください」と止まる。** 知らない行を黙って飛ばすと、切り替えた記録が
消えたように見えたうえ、そこへ書き足した時点で本当に失われるため、読めないことを明示して止める。

古い版に戻す予定があるなら、先に `~/.tock` をコピーしておく（下記）。

### バックアップ

ファイルをコピーするだけでよい。

```text
cp -r ~/.tock ~/tock-backup-2026-08-14
```

戻すときは、コピーしたディレクトリを `~/.tock` に置き直す。追記のみなので、
コピーした時点までの記録がそのまま残っている。

## 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 成功 |
| 1 | 打ち間違い・入力の不備（メッセージは stderr に出る） |
| 2 | 想定外のエラー |

エラーメッセージは stderr、通常の出力は stdout に出る。集計結果をパイプで渡しても
エラーが混ざらない。

## 今できないこと

書いていない機能は実装されていない。とくに次の点は、使い始める前に知っておくとよい。

- **時刻の表示は ISO 8601 の UTC のまま。** `2026-08-12T09:00:00.000Z` のように出る
- **`--at` や `--start` は時刻だけを指定する。** 日付は変えられないので、別の日へ記録を
  移すことはできない
- **タイムゾーンは実行環境のものを使う。** 設定では選べない
- **同時に複数のプロセスから書くことは想定していない。** 別の端末で同時に打刻すると
  記録が壊れることがある
- **集計に丸め（15分単位など）は適用されない**

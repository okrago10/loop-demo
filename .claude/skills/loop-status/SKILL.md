# loop-status

バックログの現在地を表示する。**読み取り専用。**

このスキルは以下を一切行わない。

- ファイルの作成・編集
- コミット・push・ブランチ操作
- Issue や PR の作成・更新・コメント

状態はすべて GitHub から導出する。ローカルに状態ファイルは持たない。
`git fetch` を含め、リポジトリの状態を変更しない操作のみを行う。

## 状態の導出

| 状態 | 判定方法 |
| --- | --- |
| 完了 | Issue が closed |
| 進行中 | その Issue を `Closes #N` で参照する open な PR がある |
| 指摘が残っている | PR に未解決のレビューコメント、または `CHANGES_REQUESTED` のレビューがある |
| 停止中 | Issue に「自動作業を停止しました」というコメントがある |
| 着手可能 | 上記のいずれでもなく、依存先がすべて closed または open PR あり |
| 依存待ち | 依存先の Issue が未着手（open かつ PR なし） |

依存関係は各 Issue 本文の `## 依存` セクションから読む。エピックID（`E3-1` 形式）は、
各 Issue のタイトル接頭辞 `[E3-1]` と突き合わせて Issue 番号に解決する。

バックログ全体をまとめた Issue（タイトルが `[BACKLOG]` で始まるもの）は
集計の対象外とする。

## 収集する情報

1. open / closed の Issue 一覧（番号・タイトル・本文の依存セクション）
2. open な PR 一覧（番号・base ブランチ・head ブランチ・対応する Issue）
3. 各 PR の CI 状態（成功 / 失敗 / 実行中）
4. 停止中の Issue とその停止理由（停止コメントの「停止理由」行）

## 出力

```
## バックログ進捗

完了 3 / 26   進行中 2   停止中 1   着手可能 4

## レビュー待ちの PR

  main
   └─ PR #29  Issue #1  [E1-1] プロジェクト初期化        CI ✅  ⚠ 未解決の指摘 2件
       └─ PR #30  Issue #2  [E1-2] Lint / Format の整備   CI ⏳ 実行中

  ※ スタック 2段 / 上限 5段

## 停止中

  Issue #9  [E3-1] 永続化：ストアのインタフェースと JSONL 実装
    理由: 修正試行が上限（2回）に達したため
    ブランチ: feat/9-jsonl-store

## 次の着手候補

  1. Issue #5  [E2-1][P1] Entry の型と生成・検証     依存: なし        base: main
  2. Issue #12 [E4-1][P1] CLI の骨格                 依存: #1(進行中)  base: feat/1-...

## 依存待ち

  Issue #13 [E4-2][P1] start / stop     ← #9 が停止中のため着手できない
```

## 表示のルール

- **次の着手候補の並び順は `loop-run` と一致させる**（優先度 → 依存が全て closed の
  ものを優先 → Issue 番号昇順）。ここに表示された先頭の Issue が、`/loop-run` を
  引数なしで実行したときに着手されるものになる
- 各候補には base ブランチ（`main` か、スタックする場合は親のブランチ）を併記する
- 停止中の Issue が、他の Issue の依存先になっている場合はその影響を明示する
  （ループが進めなくなっている原因を一目で分かるようにするため）
- 該当がないセクションは省略してよい（「停止中」が0件なら表示しない）

## 最後に

状態に応じて、次に取るべき行動を1〜2行で添える。

- 未解決の指摘が残っている PR がある → 人の判断待ちである可能性が高い旨
- 着手可能な候補がある → `/loop-run` で着手できる旨
- スタックが上限に達している → どの PR をマージすれば進めるか
- 停止中の Issue が後続をブロックしている → その Issue の判断が必要である旨
- すべて完了 → バックログを消化しきったこと
